# 本机识别基准（2026-11-14）

不改变识别代码，不访问云 AI，不上传任何图片或音频。评测浏览器只允许 127.0.0.1 请求。固定种子 **20261114**，按 cases.json 顺序串行执行；不要同时运行两个评测或验收，以免污染耗时。

## 重跑

需要 Node 22、Python 3、Playwright Chromium 和可选 OMR 权重。先运行 `npm ci` 和 `npm run build:static`。

```sh
timeout 200 npm run eval:generate
timeout 3550 npm run eval:omr
timeout 300 npm run eval:dictation
timeout 90 npm run eval:report
```

默认日志写在仓库的 `../r/`；可用 `EVAL_LOG_DIR=/absolute/path` 改写。OMR 每张上限 150 秒（`EVAL_CASE_SECONDS` 可改，但比较前后版本时应一致），整套预算 3300 秒，外层 timeout 3550 秒。每张结果立即写 JSONL，包含所有 Worker 消息、原始 **kern、草稿损失、超时标志、音符与小节计分，脚本异常退出不伪装成成功。中断后显式 `EVAL_RESUME=1` 可以续跑；只有同素材哈希、同代码、同参数才适合续跑。

生成目录 `eval/generated/` 不进 git、不打包进产品。仓库保留生成器、测试谱、真值 MusicXML 和清单。生成的结果和媒体分别写入 `eval/results/` 和 `eval/generated/`，运行日志写入配置的日志目录。

## 取样与真值

四首新增公有领域曲目由仓库 `examples-pd/*.ts` 重刻，导出固定片段 MusicXML，再用这份真值刻谱：巴赫前奏曲开头两小节、致爱丽丝第 3–4 小节（从 3 个四分拍起）、土耳其进行曲开头两小节、摇篮曲第 3–4 小节（从 6 个四分拍起）。前两首选源数据主声部与 voice2 做两声部练习改编（不含 extraVoices），后两首只取主声部。删掉表情与装饰元数据，音高与时值保持所选片段；这不是原版全编制的质量抽样。

必须测试的反馈原图全部保留。C 大调用随附 MusicXML。巴赫 PNG 第 1 页固定裁框 `[0,235,1654,540]`，第 2 页 `[0,65,1654,340]`，分别对应第 1–3、19–21 小节；真值取同一 Mutopia 版本的仓库源数据，保留全部声部。每页完整 PNG 和原 PDF 经产品 `renderPdf` 渲染的两页另外各跑一次，报告草稿产出、部分草稿、超时和耗时，不用三小节真值冒充全页准确率。两种已有小星星图片没有可靠逐音 MusicXML，记“不支持／无逐音真值”，不编造音高准确率；整图可用状态记 0。

五种照片版本：clean 无损 PNG；perspective 投影 + 0.9° 倾斜；lighting ±3px 正弦弯曲 + 宽阴影及光照渐变；low-quality 长边最多 1000px、0.45px 模糊、固定噪声、JPEG quality 0.52；combined 叠加全部。参数见 `transform.mjs`；所有变体保持同一裁框，不针对识别结果调整。clean 的像素等于原图／固定裁图（不含 JPEG 损失）。小尺寸原图不放大，故低清版本只施加模糊、噪声和压缩。

音频用上述四首主旋律（和弦取最高音）及自制四小节 C 大调音阶、小星星练习，共六段。实际输出 SMF MIDI，再由独立的本地 SMF 读取器取 note-on/off 和固定 tempo，按这些事件合成 22.05kHz PCM WAV；没有绕过音频检测直接导入 MIDI。clean 是加法合成器，noise 为固定白噪声，accompaniment-reverb 加低音 C 大三和弦与三次反射，phone 为 300Hz 高通／3400Hz 低通、削波、量化和底噪。伴奏也可能与原曲调性不合，这是固定干扰条件。它们是可重建的录音式模拟，不是现实手机／真人录音样本，不能外推真实钢琴、歌唱、商业录音准确率。

音频运行现有默认单音上传链 `decodeAudioData → transcribeBuffer → estimateBpm → quantizeDetected(...)`，不改阈值。自 2026-11-17 起，**官方可用**验收网格为十六分音符（`grid=0.25`）；产品界面默认网格仍是八分音符（`grid=0.5`），用户可在听写草稿里改对齐。2026-11-14 基线报告里的听写可用率是按当时官方八分网格（0.5）计的，不能与新口径混写。未覆盖用户另选的 Basic Pitch 多音模式，不能拿本报告代表其质量。

## 指标

- 不以“有草稿”冒充“能用”。草稿表示 `compileRecognition` 确实产出 Score（包括有标记的部分草稿）；听写表示检测到音符。空白修复占位不算识别成功。
- 音符事件是 `(起始, MIDI 音高, 时长)`，和弦拆为同时事件，合并全部声部，忽略谱号拼写／声部归属。休止通过后继音符起始体现，不单独当“正确音符”。同音不同声部不去重。
- 在固定真值小节边界内作最大二分匹配，不滑动整曲，不用识别结果挑选真值小节。分母为 `max(真值事件数, 输出事件数, 1)`；漏音、错音、额外音、额外尾部都受罚。音高正确要求起始+音高，时值正确要求起始+时长（不强求音高），另存起始正确数和三项全对数。部分草稿的未输出小节也在分母内。
- OMR 起始／时值容差各 0.0001 个四分拍。原始音频起始容差 80ms、时值 120ms；量化草稿起始／时值容差各 0.05 个四分拍。原始波形对 MIDI note-off 评分，释放包络导致的差异也受罚。
- 小节严格正确：该小节事件集合全对，含数量；小节可用：`max(真值事件数, 输出事件数) − 全对匹配数 ≤ 1`，即至多改／补／删一个单音事件。额外尾部计入最后一小节。没有真实草稿的小节一律不可用。未单独评分的空休止语义、表情、连线、谱号、调号与声部身份意味着本指标仍是乐观上界，不能代表出版质量。
- 主结论分别报告有 MusicXML 的小节可用率、逐图“所有小节都可用”率、草稿产出率。不支持图片保留整图失败，但没有真值的两张图不虚构音符分母。小样本、同曲衍生图高度相关，不提供假精确的统计置信度。

## 许可

新评测代码 MIT（见 LICENSE）。仅复用现有 MIT / Apache-2.0 工具：abcjs、Vite、jsdom、onnxruntime-web 为 MIT，Playwright、pdfjs-dist 为 Apache-2.0。变形及合成器为自制 Canvas／JavaScript，无新增依赖、无 GPL/AGPL 工具或音源。


比较两次运行时，先通过 `npm run eval:report` 生成基线 JSON，并另存一份。后续运行 generate、omr 和 dictation 后，执行 `npm run eval:compare -- <基线 JSON 路径>`。脚本会拒绝不完整结果、素材或计分器变化。

刻谱截图的字形栅格化还取决于 Chromium 与系统字体，基线记录浏览器版本、硬件、相关代码哈希和每张输入哈希。跨机器请使用相同运行环境；compare 遇到图片字节变化会拒绝比较，应先复原环境／素材，不能静默换一批图后沿用旧分母。性能对比也需同一硬件且串行运行。

耗时边界：图片单例秒数从 ImageBitmap 解码后发往真实 Worker 前开始，包含模型缓存读取／校验／初始化和推理，不含文件读取／位图解码；整套 wallSeconds 另含宿主调度开销。音频单例秒数包含 Web Audio 解码、检测、自动 BPM 和量化，不含离线合成／写文件。
