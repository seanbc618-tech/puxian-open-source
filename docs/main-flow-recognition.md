# 图片 / 音乐识别主流程

首页和编辑器的主入口是「识别图片」「识别音乐」。前者使用本机图片 / PDF 页面队列和 OMR worker；后者直达录音、音频上传和 MIDI 声部选择。空白谱、示例和本机存档仍可使用。

识别先保留来源预览，再进入共用的「识别草稿」对话框。在草稿谱面点选音符，可按调内音阶升降、改时值、删除或补音，也可撤销草稿修改。只有「写入主谱」才调用主编辑器的 publish / history。放弃或按 Escape 不改变主谱或其自动保存；对话框内操作不触发主谱的快捷键。

图片沿用部分恢复：逐页 / 逐系统错误、未识别区域和原始谱符均保留，损失说明带入草稿。整页无法转换时仍能打开带休止占位的可编辑草稿。音乐未听出稳定音高或推理失败时也保留占位草稿；文件无法解码时可从错误旁打开音乐草稿。占位不冒充识别出的休止，需对照原文件补音。

「辅助模块」沿用 `zone-style`，旧链接继续有效。编曲 / 简化、和弦、指法、视奏集中于此；练习工具和混音可从这里打开，底栏练习快捷入口保留。相关代码只在打开辅助模块或练习时加载，之后保留已有状态。功能栏仍为 8 项，将「听写与音频」提前，将「风格改编」改名为「辅助模块」。

草稿复用 JianpuView、shiftSelection 和 replaceVoiceAndRemap；前两项由编辑器传入，避免共享渲染组件和选段编辑库被拆出额外首页依赖。共享的惰性面板重试函数归入已有 input 分包；首页不得因此加载编辑器或增加 mapDeps。

验收新增 `verify-recognition-flow.mjs`，覆盖音乐入口、辅助模块按需加载、MIDI 草稿音高 / 时值、主谱隔离、写入 / 撤销和静音占位。图片合并验收增加草稿编辑 / 撤销及全部失败后的补音路径。`scripts/omr/feedback.mjs` 使用 feedback-r4 下的原始巴赫扫描图和两页 PDF，经真实 worker 识别后在草稿上改音，再写入、移调、撤销；阻断外部域名并检查只发本机 GET。

计时、首屏预算和布局断言保持原阈值；循环计时仍读 `/proc/uptime`，保留 4.5–8 秒断言。所有动效验收使用正常动效设置。
